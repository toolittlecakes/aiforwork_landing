## Метаконтекст для вебинара

1. Маршрут работает, когда каждый новый термин появляется после понятной рабочей потребности. Сначала участник хочет доставить отчёт в Telegram — потом узнаёт про API и токен. Сначала повторяет удачный процесс — потом узнаёт слово skill.
2. Базовая ценность Codex — делать работу в реальной папке: редактировать файлы, анализировать выгрузки, собирать презентации и публиковать результаты. Создание приложений появляется только ближе к финалу.
3. Работа с браузером — отдельный класс возможностей, а не запасной «хрупкий» путь. Он нужен для авторизованных сессий, личных кабинетов и интерфейсов без удобного API.
4. Skills — не один пункт. В прошлом марафоне это была лестница: методичка → свой skill → готовый внешний skill → адаптация → независимая проверка → автоматический запуск.
5. Автоматизация имеет смысл только после ручного успешного процесса и skill. Практика прямо строилась на повторном использовании уже пройденных задач.
6. Сильная продуктовая подача — не обещание «поддержки вообще», а конкретика заданий: рабочий результат за базовую итерацию, необязательная звёздочка, разбор решения, AMA и помощь в техническом затыке.
7. Для «аэрозольной» продажи в слайды лучше встраивать реальные задания и формулировки участников. Они одновременно объясняют технологию и доказывают, что маршрут уже проходили живые люди.
8. Первое задание прошлого потока — лучший источник для слайда настройки: открыть папку, дать агенту провести интервью, ответить голосом и сохранить сведения о себе. Создание тестового файла без рабочей цели действительно слабее.
9. Самодиагностика должна различать минимум девять наблюдаемых действий: настройка, работа с файлами, веб-страница, plugin, браузер пользователя, API/MCP, готовый skill, свой skill, автоматизация.
10. Термины в презентации должны быть вторичны по отношению к результату: «отправить отчёт в Telegram» понятнее, чем «подключить Telegram API»; «агент сам открыл ваш Chrome» понятнее, чем «неофициальная интеграция».
