# Видео-знакомство: A/B-тест

Статус: RUNNING, запущен 19 октября 2026 в 15:58:11 МСК. Счётчик Метрики: `108774715`. Эксперимент: `intro_video_v1`, Varioqub ID `77148`. [Отчёт](https://metrika.yandex.ru/ab/result/77148/?id=108774715) · [Настройки](https://metrika.yandex.ru/ab/edit/77148/?id=108774715).

## Протокол

- Проверяем влияние всей секции `#intro` после авторов: A `with_video` — текущая секция; B `without_video` — секции нет. Остальная страница, цены и источники трафика одинаковые.
- Varioqub распределяет посетителей 50/50 и сохраняет назначение. Отсутствие флага не означает контрольную группу: такой посетитель вне теста.
- Основная метрика — доля уникальных посетителей с подтверждённой оплатой (`aiforwork_order_paid`). Дополнительная — создание платёжной ссылки (`aiforwork_checkout_created`).
- В metadata заказа сохраняем эксперимент, вариант и ClientID Метрики. Подтверждением оплаты служит статус `paid` в payment-service, а не переход на страницу успеха.
- Не сравниваем «посмотрел видео» с «не посмотрел»: это самоотбор. Сравниваем назначенные варианты независимо от воспроизведения.
- Плановый период — 19 октября — 17 ноября 2026 включительно, не менее 28 полных дней. Ежедневно не выбираем победителя по колебаниям. При малом числе оплат результат считаем неопределённым.
- Учитываем только реальный трафик; QA не должен создавать целевые события или оплаченные заказы в основном эксперименте.

## Загрузка оплат

Для первого теста используется ручная загрузка CSV, без отдельного фонового процесса и новых секретов. Выполнять минимум раз в неделю: Метрика привязывает офлайн-конверсии к визитам за последние 21 день. До загрузки оплат основная метрика в Вариокубе неполная. Не откладывать первую загрузку до окончания теста.

1. `bun --install=force run scripts/export-experiment-payments.ts prepare` — прочитать production через существующий закрытый ops API. Скрипт не выводит токен и не забирает контактные данные покупателей; включает только новые `paid` заказы этого теста. При отсутствии оплат загрузка не нужна.
2. В Метрике счётчика `108774715`: Настройки → Загрузка данных → Офлайн-конверсии. Привязка ClientID, файл `tmp/intro-video-conversions/pending.csv`. Цель `aiforwork_order_paid` (ID `672505260`).
3. Дождаться успешной обработки и проверить привязку в отчёте «Офлайн-конверсии». Это может занять до трёх часов. Зафиксировать ID загрузки.
4. `bun --install=force run scripts/export-experiment-payments.ts ack <ID загрузки>` — отметить именно успешно загруженную партию. Не повторять загрузку уже принятого CSV. При неоднозначном статусе сначала проверить историю Метрики.

Журнал загруженных заказов и ожидающая партия лежат только в игнорируемом `tmp/intro-video-conversions/`. Не удалять его до завершения анализа; при переносе на другую машину переносить и журнал. Повторный `prepare` блокируется, пока ожидающая партия не подтверждена. Возвраты отдельно проверяются в базе: уже загруженные paid-конверсии автоматически не отзываются.

Дополнительная цель: `aiforwork_checkout_created` (ID `672505301`). Отправляется после получения рабочей платёжной ссылки; ожидание callback аналитики ограничено 500 мс и не блокирует оплату. Сбой аналитики отражается в `data-intro-experiment=error` и консоли; такие заказы не получают экспериментальную metadata. Блокировщики, разные браузеры и сброшенные cookies ограничивают полноту атрибуции; это тест браузерных посетителей, а не установленных личностей.
